## Context

tawk.to is the most-used live chat application in the world, embedded on millions of websites. Its backend is made of distributed services that need to react to each other's data. This work was done by a small engineering team of 4–5 people working with the CTO.

## Problem

Core workflows were tightly coupled, and downstream services needed to learn about data changes quickly and reliably without polling the primary database.

## What I did

- Worked on the team that designed and built an event-driven service on Apache Kafka, decoupling core workflows and giving services a reliable way to communicate.
- Helped build the real-time data pipeline that captures changes with MongoDB Change Streams and publishes them to Kafka for downstream consumers.
- Maintained 100% test coverage on the services I owned.
- Contributed to the team's architecture discussions.

## Impact

- Data changes reach downstream services with minimal latency.
- Core workflows are decoupled, so services can evolve independently.
